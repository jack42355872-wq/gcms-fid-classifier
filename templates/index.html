📖 分類規則與使用說明

分類機制

系統對每個 Peak 依化合物名稱套用規則式分類；規則判斷不出來的（落入 others），會自動查詢 PubChem 分子式做二次判定。

七大類別：

  • n-alkane：直鏈烷（如 tetradecane）。名稱是直鏈烷還不夠，滯留時間也要落在該碳數的標尺上，見下方「n-alkane RT 校驗」
  • iso-alkane：支鏈烷（如 3-methylpentane），以及名稱雖是直鏈烷、但滯留時間對不上標尺的峰
  • cyclic：全飽和的環烷（如 cyclohexane、decalin）。環上只要有一個 C=C 就不算 cyclic，歸 Alkene
  • Alkene：碳碳雙鍵、非芳香。包含環烯（cyclohexene、cycloheptatriene、bicyclo/spiro 的環狀多烯）
  • Aromatic：單一芳香環（苯、甲苯、二甲苯；以及 tetralin／indane／dihydronaphthalene 等只帶一個芳香環的部分氫化萘/茚類）
  • Polyaromatic：≥2 個芳香環（naphthalene、anthracene、phenanthrene、fluorene、biphenyl、azulene 等）
  • others：含氧/氮/硫/矽/鹵素等雜原子的非烴類（脂肪醇、醛、酮、酸、酯、醚、胺、氯代烷、furan 等雜環）。烴類分類體系中沒有對應類別，others 即為正解，並非「判不出來」

規則以化學字根比對，涵蓋衍生物寫法（NAPHTHALENYL、INDEN-1-ONE、PHENANTHRENOL 等）， 直鏈烷／烯涵蓋 C1–C50（含 HENEICOSANE、DOTRIACONTANE、TRITETRACONTANE 這類長鏈）， bicyclo／tricyclo／spiro 的環狀多烯歸 Alkene。

判定順序（先到先贏，順序本身就是分類慣例）：

含氧／雜原子 → 芳香環 → 不飽和 → 環 → 烷

  1. 含氧／雜原子官能基（O／N／S／Si／鹵素）→ others
  2. 部分氫化的萘／茚（只剩 1 個芳香環）→ Aromatic
  3. 多環芳烴（≥2 芳香環）→ Polyaromatic
  4. 單環芳烴 → Aromatic
  5. 不飽和（C=C，含環烯）→ Alkene
  6. 飽和環烷（只有單鍵才算）→ cyclic
  7. 烷 → 名稱含任何烷基取代基字根（METHYL／PROPYL／OCTYL…）即 iso-alkane，否則進入 n-alkane RT 校驗

第 1 條排在芳香環之前是刻意的：烴類分類體系（PIONA）的 aromatic 指「芳香烴」， 含氧的芳香化合物（phenyl ether、phenyl ketone、phenol、phthalate、phenanthrenol）屬含氧物，一律歸 others。 苯環＋環烷的 naphtheno-aromatic 則依慣例算 aromatic（第 4 條排在環烷之前）。

2026-08-26 更新：不飽和（第 5 條）已提到環烷（第 6 條）之前。 cyclic 的定義是「只有飽和單鍵的環」，所以環烯類要歸 Alkene 而不是 cyclic： CYCLOPENTENE, 4,4-DIMETHYL-、Cyclohexene, 1-methyl-、 7-BUTYL-1,3,5-CYCLOHEPTATRIENE、6,6-DIMETHYL-2-VINYL-BICYCLO[3.1.1]HEPT-2-ENE 全部算 Alkene。舊順序在這幾筆上碰巧判對（因為 "CYCLOPENTENE" 不含字串 "PENTANE"）， 但碰到 CYCLOHEXANE, ETHENYL-（乙烯基環己烷）這種寫法就會判成 cyclic —— 現在不會了。

同批修正的還有三類「含氧物被漏判」： Octadecane, 1-(ethenyloxy)-（乙烯醚，舊版判 n-alkane）、 …DECA-5,7-DIEN-1-ONE（酮，舊版判 Alkene）、 BICYCLO[3.1.1]HEPTAN-3-OL, …（CAS 倒裝寫法的醇，舊版判不出來）。 現在醇與酮改用「數字-OL／數字-ONE」的字尾規則辨識，醚類則直接吃 OXY／OXA 字根。

n-alkane RT 校驗（會改變分類結果）

直鏈烷每個碳數在同一套 GC 方法下只會出現在一個固定的滯留時間。 但 NIST 對長鏈飽和烷的質譜幾乎分不出直鏈與支鏈（碎片圖譜近乎相同）， 常常把一根 iso-alkane 回報成 DODECANE、Pentadecane 這種直鏈名。 只信名稱的話，n-alkane 會被灌水、i/n 會被低估。

判準：名稱是「沒有取代基的直鏈烷」時，去標尺上找它碳數對應的 RT。 同一個碳數若有好幾根候選峰，只有離標尺最近的那一根算 n-alkane， 其餘一律改判 iso-alkane（同碳數的其他飽和異構物）。 離標尺超過容差（預設 ±1.5 分鐘）的，同樣改判 iso-alkane。

預設標尺（Octane–Octadecane 標準品實測，單位：分鐘）：

C8C9C10C11C12C13C14C15C16C17C18
2.23.66.48.910.912.514.216.017.619.220.7

標尺跟著管柱與溫度程式走，換方法就要換數字，可在「分析設定」直接改。 三種模式：開啟（預設，標尺沒有的碳數一律 iso-alkane）、 只在標尺碳數範圍內校驗（C8–C18 之外沿用名稱判定）、關閉（只看名稱，等同舊版行為）。

備註：預設標尺只到 C18。在「開啟」模式下，C19 以上（Nonadecane、Eicosane、 Heneicosane…）與 C7 以下（Heptane）因為標尺上沒有對應值，一律被歸成 iso-alkane。 這些峰通常落在 C16+／C8- 視窗、不影響 C8–16 的主要統計，但如果你要看重質段的鏈長選擇性， 請把那些碳數的實測 RT 補進標尺，或改用「只在標尺碳數範圍內校驗」模式。

結果面板會列出每個碳數「對到哪一根峰、與標尺差多少」。 同一次分析的偏移應該平滑變化；某個碳數的偏移突然跳掉（超過 0.6 分鐘會標黃） 通常代表那根峰被圖庫認錯了 —— NIST 幾乎分不出直鏈 C18 與 C19， 實測就遇過「RT 落在 C18 位置的峰被叫成 NONADECANE」。程式不會自作主張改名，但一定會把它標出來。

溶劑扣除：樣品稀釋用的溶劑不是產物。溶劑峰在層析圖最前端、面積極大， 而且因為嚴重過載被積分成好幾個峰、NIST 比對品質很差（常回報成同分異構物）。 自動偵測從第一個峰連續往後掃，抓「RT 早於 C8 邊界」且「單峰 Conc% ≥ 門檻 或 名稱正好是己烷／其 C6H14 同分異構物」的一段，遇到第一個不符合的峰就停手； 也可以直接手動指定峰號。扣除後其餘峰正規化回 100%。

2026-08-26 更新：溶劑判定加上「名稱正好是己烷」這個條件。 原本只看濃度門檻，樣品濃度高的時候溶劑峰可能只佔 0.9%、低於門檻而完全沒被扣掉， 整份濃度分母就會與手動分帳對不起來。名稱比對用完整相等而非包含 （Hexane, 3-ethyl-4-methyl- 是 C9 產物，不會被誤扣）。

Distribution（依實測 Ret.Time 分三段，邊界可在「分析設定」調整）：

  • C8-：Ret.Time < C8 起點（預設 2.178 分鐘）
  • C8-16：C8 起點–C16 終點（預設 2.178–17.6 分鐘）
  • C16+：Ret.Time > C16 終點（預設 17.6 分鐘）

邊界應該對齊該次分析 n-alkane 標記峰的實際滯留時間，會隨管柱與溫度程式改變。 驗證報告輸出「類別 × 碳數視窗」矩陣，C8- 與 C16+ 也有完整組成，不再只有總量。

圖書館比對參考（不影響分類）：這是一個獨立的稽核功能，跟分類邏輯與加總驗證完全分開—— 不會回頭改任何一筆分類結果，純粹是額外資訊。

做法：系統用 C8／C16 兩個標記峰的滯留時間線性內插，算出「這個滯留位置照理說該是幾個碳」， 跟「化合物名稱本身寫的碳數」做比對，差 ≥3 個碳就列進參考清單，提示這個峰的 NIST 圖書館比對可能認錯了化合物身分，值得你人工核對名稱是否合理。 只對脂肪族（烷／烯／環烷）做這項檢查——這條線是拿 n-alkane 校正的， 芳香烴的滯留指數系統性偏高，套同一條線會整批誤報，所以不檢查。

分類（Category）本身，仍然只依照化合物名稱套用關鍵字規則判定， 跟這個碳數比對沒有關係；「加總驗證通過」檢查的是濃度總和對不對得起來，也是另一件事。 三者是三個獨立的檢查，只是剛好都出現在同一份結果裡。

PubChem 二次判定：關鍵字判斷不出來的化合物，系統自動查詢 PubChem 取得分子式與 IUPAC 名稱，依碳氫比例（CnH2n-6 苯環／CnH2n 烯或環／CnH2n+2 烷）與雜原子（O/N）二次分類；查詢失敗則維持 others。

使用方式

  1. 支援 Shimadzu GCMSsolution 匯出的原始 .xlsx，單一活頁簿可包含多個工作表（分頁）
  2. 系統會自動掃描「每一個」工作表：只要該工作表含 Peak# 或 Ret.Time 表頭列，就自動分類；不含的工作表視為無關資料，直接略過，不影響其他工作表
  3. 結果回寫到同一份 xlsx：每個成功分類的工作表各自加上 Category / Distribution 欄、Summary 表格、長條圖、驗證報告
  4. 檔案大小上限 16MB

常見錯誤與如何避免

  • 檔名沒有影響：分類只看工作表內容，不依賴檔案名稱
  • 表頭列必須含「Peak#」或「Ret.Time」其中之一：手動改了欄名、合併儲存格、欄名前後多了空白或特殊字元，都會抓不到表頭，該工作表會被判定為「略過」
  • Name 欄位不可留空：留空會導致無法辨識化合物名稱，該筆會落入 others
  • Conc. 欄位必須是純數字：若含文字或單位符號（如 "5.2%"、"N/A"），會被當成無效值排除在加總外，導致統計失真
  • 檔案格式必須是 .xlsx：.xls（舊版 Excel）、.csv 不支援
  • Category 欄位若已手動填寫：系統只對「空白」的列自動分類，已填寫的值會直接沿用——手動類別名稱要跟七大類別完全一致（含大小寫），拼錯（例如打成 "aromatics" 而非 "Aromatic"）會被當成新的、未預期的類別，Summary 加總會對不起來
  • 一個工作表只認第一個 Peak Table 表頭：若同一工作表內多次出現「Peak#」字樣，只有第一個會被採用
  • 可直接上傳 GCMSsolution 原始匯出檔：系統只讀取 MC Peak Table 範圍（Peak# 為數字的連續列），後面的 [MS Similarity Search Results]、[MS Spectrum] 等區塊會自動忽略，不必先手動刪掉
  • Peak# 欄位必須是連續的數字：Peak Table 中間若插入空白列或文字列，系統會判定表格在該處結束，後面的 peak 不會被分類。 例外：手動把某幾列的 Peak# 改寫成「C8」「C16」這種 n-alkane 標記（人工分帳檔的常見做法）不會中斷表格，系統看得懂

備註：規則判不出來的化合物仍會自動查詢 PubChem 分子式做二次判定（含失敗重試）。 此路徑對 R1／R2 實測為 0 筆——規則已能涵蓋全部化合物，因此結果不依賴網路、可完整重現； PubChem 保留作為遇到全新化合物時的安全網。

Classification Mechanism

Each peak is classified from its compound name using rule-based keyword matching. Anything the rules can't resolve (falls into "others") is automatically re-checked via a PubChem molecular-formula lookup.

Seven categories:

  • n-alkane: straight-chain alkanes (e.g. tetradecane). A straight-chain name is not enough — the retention time must also land on that carbon number's ruler entry; see "n-alkane RT check" below
  • iso-alkane: branched alkanes (e.g. 3-methylpentane), plus any peak carrying a straight-chain name whose retention time does not match the ruler
  • cyclic: fully saturated rings (cyclohexane, decalin). A single C=C on the ring disqualifies it — that goes to Alkene
  • Alkene: C=C double bond, non-aromatic. Includes cycloalkenes (cyclohexene, cycloheptatriene, bicyclo/spiro cyclic polyenes)
  • Aromatic: single aromatic ring (benzene, toluene, xylene; also tetralin/indane/dihydronaphthalene-type compounds that carry only one aromatic ring)
  • Polyaromatic: ≥2 aromatic rings (naphthalene, anthracene, phenanthrene, fluorene, biphenyl, azulene, etc.)
  • others: non-hydrocarbons carrying O/N/S/Si/halogen heteroatoms (fatty alcohols, aldehydes, ketones, acids, esters, ethers, amines, chloroalkanes, furan-type heterocycles). A hydrocarbon-type scheme has no class for these, so "others" is the correct answer, not a failure to classify.

Matching is done on chemical stems, so derivative spellings (NAPHTHALENYL, INDEN-1-ONE, PHENANTHRENOL…) are covered. Straight-chain alkanes/alkenes span C1–C50 (including long chains such as HENEICOSANE, DOTRIACONTANE, TRITETRACONTANE); bicyclo/tricyclo/spiro cyclic polyenes are classed as Alkene.

Decision order (first match wins — the order itself is the classification convention):

oxygenate / heteroatom → aromatic ring → unsaturation → ring → alkane

  1. Oxygen/heteroatom functional group (O/N/S/Si/halogen) → others
  2. Partially hydrogenated naphthalene/indene (only 1 aromatic ring left) → Aromatic
  3. Polycyclic aromatics (≥2 aromatic rings) → Polyaromatic
  4. Single-ring aromatics → Aromatic
  5. Unsaturation (C=C, including cycloalkenes) → Alkene
  6. Saturated rings (single bonds only) → cyclic
  7. Alkanes → any alkyl-substituent stem in the name (METHYL/PROPYL/OCTYL…) means iso-alkane; otherwise it goes through the n-alkane RT check

Rule 1 sits ahead of the aromatic rules deliberately: in a PIONA-style scheme "aromatic" means aromatic hydrocarbon, so oxygenated aromatics (phenyl ether, phenyl ketone, phenol, phthalate, phenanthrenol) are oxygenates → others. Naphtheno-aromatics (benzene ring fused to a cycloalkane) count as aromatic by convention, which is why rule 4 precedes the ring rule.

Updated 2026-08-26: unsaturation (rule 5) now precedes rings (rule 6). "cyclic" means a ring with saturated single bonds only, so cycloalkenes belong in Alkene: CYCLOPENTENE, 4,4-DIMETHYL-, Cyclohexene, 1-methyl-, 7-BUTYL-1,3,5-CYCLOHEPTATRIENE and 6,6-DIMETHYL-2-VINYL-BICYCLO[3.1.1]HEPT-2-ENE are all Alkene. The old order happened to get these right (because "CYCLOPENTENE" does not contain the string "PENTANE") but would have mis-classified spellings like CYCLOHEXANE, ETHENYL- — it no longer does.

Three classes of missed oxygenates were fixed in the same pass: Octadecane, 1-(ethenyloxy)- (vinyl ether, previously n-alkane), …DECA-5,7-DIEN-1-ONE (ketone, previously Alkene) and BICYCLO[3.1.1]HEPTAN-3-OL, … (CAS-inverted alcohol, previously unresolved). Alcohols and ketones are now matched on the "<locant>-OL / <locant>-ONE" suffix pattern, and ethers on the OXY/OXA stem.

n-alkane RT check (this one does change the classification)

Under one GC method, each n-alkane carbon number elutes at exactly one retention time. But NIST can barely separate straight- from branched-chain saturated alkanes by mass spectrum (their fragmentation patterns are nearly identical), so iso-alkanes are frequently reported under names like DODECANE or Pentadecane. Trusting the name alone inflates n-alkane and understates i/n.

Rule: when a name is an unsubstituted straight-chain alkane, look up the ruler entry for its carbon number. If several peaks compete for one carbon number, only the one closest to the ruler stays n-alkane; the rest are reclassified as iso-alkane (other saturated isomers of the same carbon number). Anything beyond the tolerance (default ±1.5 min) is likewise reclassified as iso-alkane.

Default ruler (Octane–Octadecane standards, minutes):

C8C9C10C11C12C13C14C15C16C17C18
2.23.66.48.910.912.514.216.017.619.220.7

The ruler tracks the column and oven program, so swap in your own numbers when the method changes — it is editable under "Analysis settings". Three modes: on (default; carbon numbers absent from the ruler become iso-alkane), ruler range only (outside C8–C18 the name is trusted as before), and off (name only — the previous behaviour).

Note: the default ruler stops at C18. In "on" mode, C19 and above (Nonadecane, Eicosane, Heneicosane…) and C7 and below (Heptane) have no ruler entry and are therefore classed as iso-alkane. Those peaks normally sit in the C16+ / C8- windows and do not affect the main C8–16 statistics, but if you care about chain-length selectivity in the heavy fraction, add their measured retention times to the ruler or switch to "ruler range only".

The results panel lists which peak each carbon number matched and how far it sits from the ruler. Deviation should drift smoothly across a run; a single carbon number jumping out (highlighted above 0.6 min) usually means that peak was mis-identified by the library — NIST can barely separate straight-chain C18 from C19, and a real run showed a peak sitting exactly at the C18 position being reported as NONADECANE. The tool never renames a peak on its own, but it always flags this.

Solvent exclusion: the dilution solvent is not a product. Auto-detect scans contiguously from the front of the chromatogram for peaks eluting before the C8 boundary that are either at or above a concentration threshold or named exactly as hexane / one of its C6H14 isomers, and stops at the first peak that doesn't qualify. Excluded peaks are removed from both numerator and denominator, and the rest is renormalized to 100%. Can also be set to a manual peak list or turned off in "Analysis settings".

Updated 2026-08-26: the "named exactly as hexane" condition is new. With only a concentration threshold, a concentrated sample can leave the solvent peak at ~0.9% — below the threshold, so it was never excluded and the concentration denominator disagreed with the manual reconciliation. Name matching is on exact equality, not substring, so Hexane, 3-ethyl-4-methyl- (a C9 product) is never excluded.

Distribution (by measured Ret.Time; boundaries adjustable in "Analysis settings"):

  • C8-: Ret.Time < C8 start (default 2.178 min)
  • C8-16: C8 start – C16 end (default 2.178–17.6 min)
  • C16+: Ret.Time > C16 end (default 17.6 min)

Boundaries should track the actual retention time of the n-alkane marker peaks for that run, since they shift with the column and oven program. The validation report includes a category x carbon-window matrix, so C8- and C16+ also get a full composition, not just a total.

Library-match reference (does not affect classification): this is a separate, informational-only check — it never changes any category, and it is independent of the sum validation. It interpolates, from the C8/C16 marker retention times, what carbon number a peak "should" have at that elution time, and compares it to the carbon count implied by the compound name. A mismatch of ≥3 carbons is listed as a reference item, flagging peaks where the NIST library match is likely wrong and worth checking by hand. Restricted to aliphatics (alkane/alkene/cyclic) — this line is calibrated on n-alkanes, and aromatics elute systematically later on the same scale, so applying it there would flag them in bulk incorrectly.

To be explicit: classification is decided purely by keyword rules on the compound name and has nothing to do with this carbon check; "sum validation passed" is a separate check on whether concentrations add up correctly. All three are independent checks that happen to appear in the same report.

PubChem fallback: for names the keyword rules can't resolve, the app queries PubChem for the molecular formula and IUPAC name, then classifies by C/H ratio (CnH2n-6 = benzene ring / CnH2n = alkene or ring / CnH2n+2 = alkane) and heteroatom presence (O/N). If the lookup fails, it stays "others".

How to Use

  1. Supports raw .xlsx exports from Shimadzu GCMSsolution. A single workbook may contain multiple sheets (tabs).
  2. The app scans every sheet automatically: any sheet with a "Peak#" or "Ret.Time" header row gets classified; sheets without one are treated as unrelated content and skipped, without affecting the others.
  3. Results are written back into the same xlsx — each successfully classified sheet gets its own Category/Distribution columns, Summary table, bar chart, and validation report.
  4. Max file size: 16MB.

Common Mistakes to Avoid

  • File name doesn't matter — classification only looks at sheet content.
  • The header row must contain "Peak#" or "Ret.Time" exactly: renamed columns, merged header cells, or stray whitespace/special characters will prevent detection — that sheet gets marked "skipped".
  • The Name column can't be blank: a blank name can't be resolved and falls into "others".
  • The Conc. column must be pure numbers: text or unit symbols (e.g. "5.2%", "N/A") get treated as invalid and excluded from totals, skewing the statistics.
  • File must be .xlsx: legacy .xls and .csv are not supported.
  • If the Category column is already filled in manually: the app only auto-classifies blank rows — pre-filled values are used as-is. Manual entries must match the seven category names exactly (case-sensitive); a typo (e.g. "aromatics" instead of "Aromatic") is treated as a new, unexpected category and will throw off the Summary totals.
  • Only the first Peak Table header per sheet is used: if "Peak#" appears more than once in a sheet, only the first occurrence is read.
  • Raw GCMSsolution exports can be uploaded as-is: only the MC Peak Table range (consecutive rows with a numeric Peak#) is read. Trailing sections such as [MS Similarity Search Results] and [MS Spectrum] are ignored automatically — no need to strip them first.
  • Peak# must be a continuous run of numbers: a blank or text row inserted mid-table is treated as the end of the table, and peaks below it won't be classified.
